# מסנן תוכן — תוסף דפדפן לסינון תוכן לא צנוע

תוסף Chrome (Manifest V3) שמסתיר תמונות לא צנועות בזמן אמת בעזרת NSFWJS, ומסנן
עמודים לפי מילות מפתח בעברית ובאנגלית. **כל הבדיקות רצות מקומית במחשב** — שום
תמונה, כתובת או נתון גלישה לא נשלח לשרת חיצוני.

## התקנה והרצה

```bash
npm install
```

`npm install` מוריד אוטומטית את מודל NSFWJS (`mobilenet_v2_mid`, כ-4.3MB) אל
`public/models/`. אם ההורדה נכשלה, אפשר להריץ שוב:

```bash
npm run model
```

בנייה:

```bash
npm run build
```

טעינה בדפדפן:

1. `chrome://extensions`
2. להפעיל "מצב מפתח" (Developer mode)
3. "טעינת תוסף לא ארוז" (Load unpacked) → לבחור את תיקיית `dist`

## איך זה עובד

| רכיב | תפקיד |
|------|-------|
| `src/content/content.ts` | רץ בכל עמוד ופריים. מסתיר תמונות עד שהן נבדקות, שולח כל תמונה לבדיקה, מחליף תמונות חסומות בפלייסהולדר, וסורק את טקסט העמוד. |
| `src/background/service-worker.ts` | נתב. מוודא שמסמך ה-offscreen חי, מעביר אליו בקשות, ושומר מטמון תוצאות לפי כתובת. |
| `src/offscreen/offscreen.ts` | מסמך ה-offscreen — המקום היחיד בתוסף עם DOM ו-WebGL, ולכן כאן רץ המודל. |
| `src/popup/` | מתג הפעלה מהיר, מתג לאתר הנוכחי, ומונים. |
| `src/options/` | הגדרות מלאות: ספי חסימה, מילים נוספות, רשימות אתרים. |

זרימת בדיקת תמונה:

```
img נכנס לתצוגה → content.ts → service-worker (מטמון) → offscreen (NSFWJS)
                                                             ↓
                     פלייסהולדר אטום ← 'blocked' ← ציון משוקלל מול הסף
```

### איך מחושב הציון

המודל מחזיר חמש קטגוריות. הציון המשוקלל הוא:

```
Porn + Hentai + (Sexy × משקל Sexy) + (Drawing × משקל Drawing)
```

בהגדרות מופיעה **רמת הקפדה** באחוזים — גבוה יותר = מחמיר יותר. פנימית היא
נשמרת כסף חסימה הפוך (`threshold = 1 − אחוז`), כי המודל מחזיר ציון שצריך לעבור
סף. ההמרה נמצאת ב-[options.ts](src/options/options.ts), וההחלטה עצמה ב-service
worker — כך שינוי ברמת ההקפדה משפיע מיד גם על תמונות שכבר במטמון.

ציון שעובר את הסף (ברירת מחדל: 55% הקפדה) → התמונה מוסתרת לגמרי: ה-`src` מוחלף
בפלייסהולדר, `srcset` ותגי `<source>` מנוקים, ואם האתר מחזיר את המקור — היא
נחסמת שוב.

### סינון לפי כותרת המוצר

לפני שתמונה נשלחת למודל, נבדק הטקסט שלידה: ה-`alt`, כותרת הקישור העוטף, ה-slug
של הכתובת, והטקסט של כרטיס המוצר. אם מופיע שם פריט לבוש מהרשימה ("בגד ים",
"ביקיני", "lingerie") — התמונה נחסמת מיד, בלי להמתין לסיווג.

בחנות אונליין זה מדויק בהרבה ממודל הראייה, וגם מיידי. הרשימה ב-
[keywords.ts](src/shared/keywords.ts) ויש לה בדיקת רגרסיה:

```bash
npm run test:keywords
```

הבדיקה מריצה כותרות מוצר אמיתיות משני הכיוונים — כאלה שחייבות להיחסם וכאלה
שאסור שייחסמו ("סינר תחרה", "סיכות בגדלים שונים", "כל מיני"). **כל תוספת לרשימה
צריכה לעבור אותה**, כי רשימות כאלה נוטות לתפוס יותר מדי.

הטקסט נאסף מהאב הראשון שיש בו תוכן, ועוצר אם הטקסט ארוך מ-300 תווים — אחרת
פריט אחד לא צנוע היה חוסם את כל התמונות סביבו ברשת המוצרים.

### סינון טקסט

נסרקים הכותרת, הכתובת, תגיות ה-meta ותוכן העמוד מול רשימה מובנית (עברית
ואנגלית) בתוספת מילים אישיות. ברירת המחדל: **ארבעה ביטויים שונים** חוסמים את
העמוד כולו. הרשימה בעברית מתחשבת בתחיליות (ב, ה, ו, ל, מ, ש, כ), ובאנגלית נדרש
גבול מילה מלא — כדי לא לחסום עמודי חדשות, רפואה או לימוד בטעות.

בנוסף יש רשימת דומיינים מובנית שנחסמת מיד, עוד לפני שהעמוד נטען.

## החלטות תכנון

**למה offscreen ולא בתוך סקריפט התוכן?** service worker ב-MV3 לא יכול להריץ
WebGL. טעינת המודל בכל לשונית בנפרד הייתה מבזבזת מאות מגה-בייט. מסמך ה-offscreen
טוען את המודל פעם אחת לכל הדפדפן.

**למה התמונה נמשכת שוב ב-offscreen ולא נשלחת מהעמוד?** קנבס שצויירה לתוכו תמונה
ממקור אחר הוא "tainted" ולא ניתן לקרוא ממנו פיקסלים. ה-offscreen פועל בהרשאות
התוסף ולכן יכול למשוך את התמונה ישירות. המחיר: תמונות שדורשות עוגייה או Referer
עשויות להיכשל — יש הגדרה "חסימה כשהבדיקה נכשלה" למי שמעדיף להחמיר.

**למה מייבאים מ-`nsfwjs/core`?** נקודת הכניסה הראשית של nsfwjs גוררת שלושה
מודלים ארוזים בתוך החבילה, כ-35MB. `core` מקבל כתובת מודל משלנו ומדלג עליהם —
הבנייה ירדה מ-35MB ל-1.9MB.

## כשתמונה לא נחסמה — איך לאבחן

בהגדרות, בקטע "נתוני שימוש", יש מתג **מצב אבחון**. כשהוא דולק כל תוצאת סיווג
נרשמת לקונסול של העמוד (F12 ← Console):

```
[מסנן תוכן] safe | ציון 0.183 מול סף 0.45 | Neutral=0.812 Sexy=0.183 Porn=0.004 …
```

מה לחפש:

- **אין שום שורה** → סקריפט התוכן לא רץ. לוודא שהתוסף מופעל ושהאתר אינו ברשימת
  "אתרים שבהם התוסף כבוי".
- **`error`** → לא ניתן היה למשוך את התמונה (עוגייה, Referer, CORS). אפשר להדליק
  "חסימה כשהבדיקה נכשלה".
- **`safe` עם ציון קרוב לסף** → להעלות את רמת ההקפדה או את משקל Sexy.
- **המונה "נבדקו" בפופאפ נשאר 0** → המודל לא נטען; הודעת השגיאה מופיעה בפופאפ.

## מגבלות ידועות

- **וידאו לא נסרק.** רק תמונות ותמונות רקע ב-CSS. דגימת פריימים אפשרית להוספה.
- **תמונות ב-`blob:`** שנוצרו בעמוד עצמו אינן נגישות לתוסף ולא נבדקות.
- **הבדיקה עולה זמן.** התמונה הראשונה בכל לשונית ממתינה לטעינת המודל (~1.5 שניות
  פעם אחת לכל הדפדפן), ואחריה כ-100ms לתמונה.
- **NSFWJS מאומן על פורנוגרפיה, לא על צניעות.** הקטגוריה `Sexy` היא קטגוריית
  שאריות רחבה ולא מדד לחשיפה, ולכן העלאת משקלה מכניסה גם תמונות אופנה רגילות.
  בנוסף, ביצועי המודל אינם אחידים בין גווני עור — זהו ליקוי בנתוני האימון שלו
  שאי אפשר לכוונן החוצה. **בחנויות אונליין הסינון לפי כותרת המוצר אמין יותר
  ממודל הראייה**, ולכן הוא רץ ראשון.
- **שיפור אפשרי שלא מומש:** שלב שני של פילוח גוף (BodyPix) שדוגם את גוון העור
  מהפנים של אותו אדם ומודד את שיעור החשיפה בזרועות, ברגליים ובגו. ההשוואה
  פנים-אל-גוף עוקפת את הטיית גווני העור. עלות: כ-5MB וכ-200ms לתמונה.
- **זה אינו כלי אכיפה.** משתמש שיודע להיכנס ל-`chrome://extensions` יכול לכבות
  את התוסף. זהו כלי עזר למי שרוצה בו, לא מנעול.
